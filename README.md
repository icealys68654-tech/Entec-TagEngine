# Entec Platform

Modular snapshot ingestion, 12-dimensional vector parsing, SQLite-backed diff analysis, and passive intrusion detection signal console.

## Architecture & Pipeline

The platform separates storage/vector computation (**TagEngine**) from orchestration and operator triage (**Entec Umbrella**):

```text
INGEST ──► ABSTRACT ──► TAGENGINE VECTOR_PARSE ──► SQLITE DIFF ──► PUBLISH
```

1. **TagEngine (`packages/tagengine`)**: Runs as an isolated backend service. Parses Windows `dir /s` manifests into 12-dimensional normalized feature vectors, persists snapshots and JSONL alerts in SQLite, and executes disk-backed diffs.
2. **Entec Umbrella & Operations Dashboard (`packages/umbrella`)**: Orchestrates snapshot workflows and serves the operations console. Communicates with TagEngine strictly server-to-server over HTTP using a bearer token.

> **Security & Operational Notice:** All severity scores and alerts generated by this pipeline are **review signals only**, not definitive malware verdicts. The engine is strictly passive—it does not quarantine, block, or delete filesystem objects.

## 12-Dimensional Vector Schema

Each parsed filesystem entry is projected into a normalized 12D feature vector:

| # | Dimension | Description |
|---|---|---|
| 1 | **Executable** | Binary/executable extension indicator (`.exe`, `.dll`, `.sys`, etc.) |
| 2 | **Archive / Image** | Compressed archive or disk image indicator (`.zip`, `.iso`, `.7z`, etc.) |
| 3 | **Script / Config** | Script or configuration file indicator (`.ps1`, `.bat`, `.vbs`, `.json`, etc.) |
| 4 | **Recycle-Bin Path** | Located inside `$Recycle.Bin` or deleted-item paths |
| 5 | **System / Program Path** | Located in protected OS or program directories (`Windows`, `Program Files`) |
| 6 | **Hidden / Dot Path** | Hidden attribute or dot-prefixed file/directory name |
| 7 | **Reparse Point** | Junction, symlink, or filesystem reparse point flag |
| 8 | **Directory** | Entry represents a directory rather than a regular file |
| 9 | **Normalized Path Depth** | Directory nesting depth normalized across the snapshot |
| 10 | **Normalized Log Size** | Log-scaled byte size normalized against snapshot distribution |
| 11 | **Recency** | Modification/creation proximity relative to the snapshot time anchor |
| 12 | **Timestamp Anomaly** | Chronological inconsistencies (e.g., future timestamps or skewed metadata) |

## Environment Variables

Configure secrets via a secret manager or a local `.env` file (never commit `.env` or expose tokens in browser-delivered code).

| Variable | Service | Required | Description |
|---|---|---|---|
| `ENTEC_API_TOKEN` | TagEngine | Yes (Prod) | High-entropy bearer secret required on `POST /api/analyze`, `/api/snapshots`, `/api/snapshot-comparisons`, and `/api/maintenance/retention`. Fails closed (`503`) in `NODE_ENV=production` if unset. |
| `TAGENGINE_API_TOKEN` | Umbrella | Yes | Matching bearer token sent server-side by `TagEngineClient` in `Authorization: Bearer <token>` headers. Never sent to the browser. |
| `ENTEC_SNAPSHOT_DIR` | TagEngine | Recommended | Durable writable directory for SQLite databases, raw snapshots, and JSONL vectors (default: `./data/snapshots`). |
| `TAGENGINE_URL` | Umbrella | Yes | Private network URL where TagEngine is reachable (default: `http://127.0.0.1:3000`). |
| `ENTEC_DASHBOARD_HOST` | Umbrella | Optional | Bind address for the operations console (default: `127.0.0.1`). |
| `ENTEC_DASHBOARD_TOKEN` | Umbrella | Remote only | Separate token required when binding the dashboard remotely behind TLS and an authenticated reverse proxy. |

## Quick Start

### 1. Install & Build
```bash
npm run install:all
npm run build:all
```

### 2. Start TagEngine (Process 1)
```bash
NODE_ENV=production \
ENTEC_API_TOKEN="your-shared-secret" \
ENTEC_SNAPSHOT_DIR="./data/snapshots" \
npm run start:tagengine
```

### 3. Start Entec Operations Dashboard (Process 2)
```bash
TAGENGINE_URL="http://127.0.0.1:3000" \
TAGENGINE_API_TOKEN="your-shared-secret" \
npm run start:dashboard
```

The operations console listens on `http://127.0.0.1:4173` by default.
